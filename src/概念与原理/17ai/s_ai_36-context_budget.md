# Context Budget：调模型前的上下文预算

## 概念

两个词容易混：

| | 是什么 | 谁负责 |
| --- | --- | --- |
| **Context Window** | 单次调用的容量上限（Token） | 模型 / 服务商 |
| **Context Budget** | 在窗口内「放什么、放多少、怎么压缩」的策略 | 应用代码 |

窗口是一次调用的**硬约束**（见 [上下文窗口](./s_ai_21-context_window)），预算是在这个约束下的**分配与取舍**。数怎么算见 [Token 的工程账本](./s_ai_34-token_budget)，本篇讲策略。

## 为什么需要

不做预算，Agent 会同时踩四个坑：

- **窗口**：输入 + 输出一起撞上限。
- **成本**：多轮调用反复重发同一段历史。
- **延迟**：输入越长，首 Token 越慢。
- **干扰**：无关、重复、过时的内容稀释了真正相关的信息。

## 预算里都有什么

| 内容 | 管理重点 |
| --- | --- |
| 系统 / 开发者指令 | 保留必要约束，删掉冗余 |
| 当前用户问题 | 保留完成任务所需信息 |
| 对话历史 | 按相关性与时间选，不按「全都要」 |
| 摘要 / 记忆 | 注意准确性、时效、来源 |
| RAG 文档 | 优先相关且可靠，控制条数与长度 |
| 工具定义 | 只给当前需要或允许的工具 |
| 工具结果 | 保留关键字段，裁掉无关字段 |
| 输出预留 | 按任务与服务限制留 |
| 安全余量 | 应对估算误差与格式开销 |

预算不必固定切块。普通问答、长报告、多工具 Agent 的比例完全不同，要按任务调。

一个关键约束：

```text
输入 Token + 本次输出预留 ≤ 上下文窗口
```

输出预留**不要把已生成和待生成重复计算**；若服务把推理内容也计入窗口，按其规则算。

## 课程里的 220 Token 示例说明了什么

把窗口人为压到 220 Token：输出留 60、资料/工具留 40，当前消息只剩 120。

做法是：把旧对话里的「订单金额 3000」写进摘要，再尽量保留较近的历史。于是即使原始对话没发，模型仍可能从摘要看到这个事实。

要点不是这个比例，而是：**压缩不等于删除全部旧信息，也可以换一种形式保存。**

> 课程里的 Token 数是简化算法估算的，不是真实 Tokenizer，不能用来保证请求不超限。

## 保留什么：三个判据

1. **任务必需优先**：当前订单、可信状态与金额、适用规则、未完成的工具调用、安全约束。
2. **重要性 ≠ 时间**：最近的不一定重要，早期给出的关键规则可能不能丢。
3. **关键事实带元信息**：来源、时间、是否已核实。

## 摘要的四个风险

| 风险 | 例子 |
| --- | --- |
| 漏掉关键条件 | 丢了「超过 2000 元需人工审核」的例外 |
| 说法变事实 | 用户说「退了 3000」→ 摘要写成「已退款 3000」 |
| 旧规则当新规则 | 引用已失效的政策版本 |
| 错误累积 | 摘要的摘要，偏差被放大 |

还有一条容易忽略：**摘要不会因为位置高就获得权限**。摘要里夹带的「AI 应自动退款」仍然是外部内容，不能升级成系统指令，更不能替代代码校验。

## 工具调用要成组保留

```text
assistant: 发起工具调用（含调用 ID）
tool:      返回结果（引用同一 ID）
```

只留一半，模型就缺执行背景，或者请求格式不合法。裁剪时按 API 要求成组处理。

## 调模型前的七步

```text
确认窗口/输入/输出限制 → 预留输出与余量 → 放指令和当前任务
→ 收集历史/记忆/RAG/工具结果 → 按相关性与可信度选择或压缩
→ 用目标模型的方式复核最终请求 → 信息完整才调用
```

放不下时的正确动作：

- 重新取更精简的可信数据；
- 拆成多步；
- 让用户缩小范围；
- 换模型或方案；
- 实在做不了就**明确停下并说明**，而不是赌「截断也能跑」。

注意：**预留只是规划，最终要按实际请求复核**。Agent 每轮工具结果都会改变输入，必须每次调用前重算，不能只在任务开始时查一次。

## 观察用量与结束原因

| 字段 | 含义 |
| --- | --- |
| `prompt_tokens` | 输入用量 |
| `completion_tokens` | 输出用量 |
| `total_tokens` | 合计 |
| `finish_reason` | 结束原因 |

`finish_reason` 要处理：`stop` 正常；`length` 表示被长度截断，输出可能不完整；其他值（工具调用、内容过滤等）按服务文档处理。**只读回答文本、不看结束原因，是常见事故源。**

缓存能降费，但**命中不代表不占窗口**，也不保证每次命中。

## 四条工程结论

1. **大窗口 ≠ 不用管理**：能放进去，不等于值得放进去。
2. **RAG / Memory / Tool 都在抢窗口**：三者要一起决策，而不是各自加料。
3. **每次调用都要重新算**：工具结果一回来，预算就变了。
4. **评估预算策略看结果**：信息是否够、规则/状态有没有理解错、工具结构是否完整、成本延迟是否下降、信息不足时能否安全停。

节省 Token 是手段，**可靠完成任务才是目标**。
