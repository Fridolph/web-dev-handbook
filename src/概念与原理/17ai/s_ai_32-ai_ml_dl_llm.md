# AI、机器学习、深度学习与 LLM：层级、训练与评估

## 概念

AI、机器学习、深度学习、大语言模型经常被并排提起，但它们不是同一层次的概念，而是**一条包含链 + 两个正交视角**：

```text
人工智能（AI）：构建智能系统的广泛领域
└── 机器学习（ML）：让模型从数据中学习
    └── 深度学习（DL）：用较深的神经网络学习
        └── 现代大语言模型（LLM）
```

| 概念 | 回答的问题 |
| --- | --- |
| AI | 系统能不能完成感知、推理、决策、语言等任务 |
| 机器学习 | 规则是不是从数据里学出来的 |
| 深度学习 | 是不是用多层神经网络学的 |
| 大语言模型 | 是不是一类以语言任务为主的模型 |
| 生成式 AI | 系统能不能**生成**文本、图片、音频（能力视角，横切） |
| Agent | 系统怎么围绕目标**组织**模型、工具和业务（系统视角，不在模型分类里） |

一句话：**包含关系是 AI ⊃ ML ⊃ DL ⊃（现代）LLM；生成式 AI 是能力视角，Agent 是系统视角。**

> 常见误读：把 Agent 当成「LLM 的下一层模型」。Agent 不是模型，是一套应用设计方式。详见 [从聊天机器人到 Agent](./s_ai_31-chatbot_to_agent)。

## 规则程序 vs 机器学习

| | 普通程序 | 机器学习 |
| --- | --- | --- |
| 规则来源 | 开发者手写 | 从数据中学 |
| 流程 | 输入 + 规则 → 结果 | 数据 + 训练方法 → 模型；新输入 + 模型 → 结果 |
| 适合 | 金额阈值、权限、格式校验 | 图片损坏识别、语义理解等难穷举的情况 |

两者**不互斥**：模型负责识别图片，退款条件与权限交给业务代码校验。工程上要判断哪部分该交给模型。

## 训练 vs 推理

以图片手势分类实验为例：

| 术语 | 在实验里指什么 |
| --- | --- |
| 样本 / 标签 | 一张手势图片 / 图片对应的类别 |
| 参数 | 模型内部被训练调整的数值 |
| 训练 | 用数据调整参数，让模型更适合任务 |
| 推理 | 用训练好的模型处理新输入 |

实验里人工标了类别，属于**监督学习**；三大范式（监督 / 无监督 / 强化）见 [机器学习](./s_ai_2-machine_learning)。

注意：模型「学习」是通过数据调整参数、形成输入输出关系，**不等于像人一样理解了任务**。

## 迁移学习：为什么少量样本也能训练

迁移学习的做法是**复用已有模型的能力，再用少量样本适配新任务**，而不是从零训练一个图像识别模型。

边界：迁移学习不等于「少量数据一定够用」。样本是否覆盖真实场景、标签是否正确，仍然决定效果。

## 模型可能学到「不可靠线索」

典型例子：训练集里「握拳」总是白墙背景，「张开手掌」总是电脑屏幕背景。模型可能靠背景分类，换背景就失效。

| 概念 | 含义 |
| --- | --- |
| 虚假相关 | 背景与类别在训练数据里相关，但真实场景未必成立 |
| 捷径学习 | 模型抓住容易获得但不可靠的线索完成任务 |
| 分布变化 | 实际输入分布与训练时不同，效果下降 |

判断纪律：**单次误判只能提示可能性，不能证明模型只看背景**。要控制变量、增加样本、重复测试。

## 独立评估：划分与泄漏

| 数据 | 用途 |
| --- | --- |
| 训练集 | 训练模型、调整参数 |
| 验证集 | 比较方案、调训练设置 |
| 测试集 | 方案确定后，评估未见数据上的表现（泛化能力） |

划分还要防**泄漏**：视频里相邻帧几乎一样，随机分到训练集和测试集，分数会虚高。划分单位应与真实使用场景一致（按视频、按用户、按时间切）。过拟合与验证集的细节见 [过拟合与正则化](./s_ai_14-overfitting_regularization)。

## 分数 ≠ 概率

分类模型输出「握拳 95%」，表示模型更倾向这个类别，**不代表现实中有 95% 的概率正确**。如果只训练了两个类别，画面里根本没有手，它仍可能给出高分。

迁移到 LLM / Agent 上：**自信、流畅、少量示例成功，都不能替代针对真实任务的评估**。详细机制见 [模型幻觉](./s_ai_20-hallucination)。

## 手势实验的问题 → LLM / Agent 的对应

| 手势模型 | LLM / Agent |
| --- | --- |
| 训练数据与真实场景不同 | 测试问题与真实用户请求不同 |
| 依赖背景等错误线索 | 依赖表面措辞，而非理解真实约束 |
| 少量样本上表现好 | 少量提示词示例成功，不代表稳定 |
| 高分不保证正确 | 回答自信，不代表有事实依据 |
| 换背景可能失败 | 工具超时、信息缺失、规则变化后可能失败 |

## 四条工程原则

1. 不只看能不能完成一个示例，还要看**失败条件**。
2. 测试数据覆盖真实场景与边界情况。
3. 检查模型是否依赖了不可靠线索。
4. 高风险操作交给业务校验、权限控制和必要的人工参与。

## 关于 AlphaGo 的常见误读

AlphaGo **使用了机器学习**：训练过的深度神经网络 + 搜索算法。它不能当作「不依赖训练数据的 AI」的例子；真正属于「不用机器学习」的是纯人工规则 + 搜索的棋类程序。
