# Model Router：任务画像、能力路由与执行边界

## 概念

Model Routing 不是「选哪个模型」，而是**为每个任务选一条处理路径**：业务代码、文本模型、推理模式、多模态能力，或几者的组合。

```text
Task Profiler（任务画像） → Model Router（选路径） → Executor（真正执行）
```

它要回答的不只是「用哪个模型」，而是：这任务需要模型吗？要什么输入？有没有确定性规则？结果怎么校验？模型挂了怎么办？

## 五类任务，五种处置

| 任务 | 更合适的方式 |
| --- | --- |
| 把审核结论改写成客服话术 | 文本模型或确定性模板 |
| 比较金额与阈值 | 业务代码 |
| 分析多条政策的适用关系 | 模型辅助 + 业务校验 |
| 识别商品照片是否破损 | 图片能力 + 必要时人工复核 |
| 真正执行退款 | 业务系统（权限、规则、幂等） |

## 能力是维度，不是互斥的三类

「普通模型 / 推理模型 / 多模态模型」只是入门分法。实际一个模型可能同时支持文本、图片、推理模式和工具调用。

设计时该问的是：**当前任务需要哪些能力？**

- **推理模式**更贵、更慢，且**不保证更正确**，要在目标任务上评估。
- **多模态**只能提供部分证据，之后仍要查订单、跑规则。
- 用户没提到风控标记，不等于订单没有风控标记。

## 什么时候优先用代码

规则明确（如「超过 2000 元需人工审核」）时，一行代码就够，好处是：可测试、可验证、可审计、版本可追溯、不需要模型猜。

但代码判断可靠有前提：金额来自可信系统、单位精度正确、阈值来自现行规则、边界与异常已处理、权限已验证。

> 需要人工审核 ≠ 退款已批准 ≠ 退款已执行。

## 任务画像长什么样

| 字段 | 示例 | 用途 |
| --- | --- | --- |
| 任务类型 | 改写 / 金额判断 / 政策分析 | 描述目标 |
| 输入模态 | 文本 / 图片 | 决定能力 |
| 数据状态 | 是否已有可信订单 | 能否跑规则 |
| 风险等级 | 普通 / 高风险 | 触发安全约束 |
| 期望输出 | 文本 / 结构化 | 决定校验方式 |
| 资源约束 | 成本 / 延迟 | 选模型或模式 |

路线通常是枚举：`deterministic_code` / `normal_text` / `reasoning_text` / `vision_plan` / `need_input`。

真实任务常常是**组合计划**：图片识别 → 查订单 → 规则判断 → 人工审核 → 生成回复。

## 路由 ≠ 计划 ≠ 结果

| 层 | 含义 |
| --- | --- |
| 路由结果 | 准备用什么能力 |
| 执行计划 | 准备按什么顺序处理 |
| 执行结果 | 实际发生了什么 |

计划里写了「调用视觉模型」，不代表真的调用了。**要看调用记录与工具返回。**

## 路由 ≠ 授权

| 谁 | 回答什么 |
| --- | --- |
| Model Router | 这个任务适合用什么能力 |
| Authorization | 当前用户有没有权限 |
| Business Rules | 当前状态允不允许操作 |

三者不能互相替代。即使路由判断「该调退款工具」，业务服务仍要独立校验身份、订单归属、退款权限、状态金额、人工确认、幂等。

同理：**客户端传来的 `task.type` 不是权限证明**。

## 测试要覆盖什么

基础单测（路线映射、阈值边界、订单不存在、缺图片、非法类型）只能证明**代码按预期跑**。上线前还缺：

- 阈值等于 / 低于 / 高于的边界；
- 模型超时、异常响应、`finish_reason !== 'stop'`；
- 权限与跨租户访问；
- 真实订单与规则服务的集成；
- 提示注入与恶意附件；
- 路由误判与降级路径。

> 测试证明代码，评估集证明模型。

## 从 Demo 到生产要补的六件事

1. **策略配置化**：模型名、阈值、超时、降级路径进配置，有审批与回滚。
2. **权限分离**：路由、鉴权、业务规则三套逻辑各管一段。
3. **输出可信度**：结构校验、范围校验、与可信数据比对、人工兜底；格式对不等于语义对。
4. **数据与密钥**：Key 只在后端；日志脱敏；附件做类型、大小、安全扫描。
5. **降级方案**：模型挂了用模板；数据不可用就说明无法判断；结果不确定就回查。
6. **可观测与评估**：记录路由是否正确、事实是否被改写、降级是否生效、人工介入率、成本延迟。

降级**不能绕过**权限、风控和人工审核。

## 五个误区

| 误区 | 实际 |
| --- | --- |
| 推理模型一定更正确 | 不一定，要按任务评估成本/质量/延迟 |
| 有图就必须只走多模态 | 图可能无关；之后仍要查订单跑规则 |
| 模型分析完规则就能退款 | 分析 ≠ 授权 ≠ 已执行 |
| 计划写了就等于执行了 | 看调用记录和业务状态 |
| 路由对了系统就安全 | 权限、校验、审计、降级要独立设计 |
