# 学习自测：同事说「这个 Agent 能自动退款」，你怎么审？

> 📚 参考：[随机性、幻觉与能力边界](/概念与原理/17ai/s_ai_37-boundaries) | [Context Budget](/概念与原理/17ai/s_ai_36-context_budget) | [模型幻觉](/概念与原理/17ai/s_ai_20-hallucination)

**场景**：同事发来一个 demo：「退款 Agent 跑通了，输入订单号就能自动审核并退款，演示时秒回。」请你上线前 review。

**考察点**：信息 / 行动 / 决策三个边界、模型改写校验、失败路径与降级、demo 与生产系统的差距。

::: details

## 核心回答

先问三个问题，对应三条边界：

| 边界 | 要问的 | 不可接受的回答 |
| --- | --- | --- |
| 信息 | 订单状态、金额、规则版本从哪来？ | 「模型自己判断」「有缓存」 |
| 行动 | 退款接口真的调了吗？回执怎么读？ | 「模型说已退款」 |
| 决策 | 金额阈值、权限、风控谁算？ | 「prompt 里写清楚了」 |

任何一条答不上来，就不是「能自动退款」，只是「能生成一段退款说明」。

## 上线前 review 清单

| 检查项 | 危险信号 | 该有的样子 |
| --- | --- | --- |
| 主流程 | 函数定义了没调用（`main;`） | 有入口、能复现 |
| 边界输入 | 订单不存在直接崩 | 显式 404 / 提示 |
| 失败路径 | 模型超时就整个失败 | 返回已算好的模板结论 |
| 输出校验 | 不校验模型改写 | 核对订单号、金额、动作 |
| 规则完整性 | 只判断金额 | 状态、期限、权限、重复申请 |
| 执行真实性 | 没有退款回执 | 调接口并读真实状态 |
| 幂等 | 重复请求会重复退 | 业务侧幂等键 |
| 可观测 | 不记录调用与决策 | 审计日志 + 用量 |

## 两个最容易漏的点

**1. 模型只负责润色，也会改错。**它可能改订单号、把「需要审核」写成「已批准」、加一个不存在的到账时间。所以要么用确定性模板，要么对模型输出做一致性校验。

**2. 演示用的是「成功路径」。**真上线遇到的是：订单不存在、接口超时、用户重复提交、金额边界 2000.00、规则刚改版。这些不处理，demo 越顺，事故越大。

## 面试回答要点

- 用「信息 / 行动 / 决策」三条边界快速定位问题。
- 指出模型输出不能作为业务事实，必须回源校验。
- 能列出至少 3 个失败路径与降级策略。
- 知道 demo 与生产之间差的是异常、幂等、审计、人工兜底。
