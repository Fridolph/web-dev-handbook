# 学习自测：老板要求「全部换成推理模型，效果更好」，你怎么评估？

> 📚 参考：[Model Router：任务画像与能力路由](/概念与原理/17ai/s_ai_38-model_router) | [随机性、幻觉与能力边界](/概念与原理/17ai/s_ai_37-boundaries) | [AI Agent 智能体](/概念与原理/17ai/s_ai_24-agent)

**场景**：客服 Agent 现在按任务分流（代码判断金额、普通模型写话术、推理模型做政策分析）。老板说：「推理模型更聪明，全部换成它，别搞那么复杂。」

**考察点**：能力维度与任务匹配、成本与延迟、评估方法、代码优先原则、降级设计。

::: details

## 核心回答

不要直接答应，也不要直接拒绝，先按「任务 → 能力」拆开看：

| 任务 | 需要推理吗 | 换推理模型的问题 |
| --- | --- | --- |
| 金额与阈值比较 | 不需要 | 用代码更快更准，模型只会引入不确定性 |
| 改写客服话术 | 不需要 | 推理模式更慢更贵，还更容易「自由发挥」改事实 |
| 多条件政策分析 | 可能需要 | 值得试，但要评估准确率与成本 |
| 图片破损判断 | 不是推理问题 | 需要视觉能力，推理再强也看不见图 |

## 评估四步

1. **按任务建评估集**：每类任务 30～100 条真实样本 + 边界样本，固定评分标准。
2. **对照跑**：现方案 vs 全推理模型，比准确率、事实错误、格式合规、P95 延迟、单任务成本。
3. **算账**：推理 token 通常更多、延迟更长，成本可能是原来的数倍。
4. **看降级**：推理服务不可用时有没有回退？回退后业务还能不能跑？

## 结论怎么给

- 用数据说话：哪类任务提升明显、哪类没提升甚至变差；
- 该用代码的继续用代码（阈值判断不是模型该干的活）；
- 要换就**按路由换**，而不是全局换；
- 保留评估集，用于后续模型升级的回归。

## 面试回答要点

- 先问「这个任务需要什么能力」，而不是「哪个模型更强」。
- 能区分推理能力、文本能力、多模态能力，不是互斥三选一。
- 强调评估集 + 成本延迟，而不是单次演示效果。
- 明确边界：换模型不改变权限、规则与执行校验。
