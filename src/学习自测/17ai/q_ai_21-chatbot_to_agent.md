# 学习自测：模型、应用与 Agent 各自负责什么？

> 📚 参考：[从聊天机器人到 Agent](/概念与原理/17ai/s_ai_31-chatbot_to_agent) | [AI Agent 智能体](/概念与原理/17ai/s_ai_24-agent) | [Function Calling](/概念与原理/17ai/s_ai_25-function_calling)

**场景**：同事问："既然接了大模型，为什么订单查询、退款校验还要我们自己写代码？模型不是能直接搞定吗？"

**考察点**：模型 / 应用 / Agent 的职责边界；上下文与记忆的区别；工具调用由谁执行；JSON 合法性与业务校验。

::: details

## 核心回答

模型只负责**根据本次上下文生成内容**；上下文准备、数据获取、权限校验、工具执行、结果校验、界面展示都在应用侧。

```text
用户输入 → 应用组装上下文 → 模型生成（可能附带工具调用请求）→ 应用执行/校验 → 展示或继续下一轮
```

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 大语言模型 | 理解输入、生成内容、输出工具调用请求 | 查数据库、执行操作、保证事实正确 |
| 应用 / 业务代码 | 组装上下文、权限、规则校验、执行工具、组装响应 | 生成自然语言解释 |
| Agent 设计 | 围绕目标选择下一步、读取结果决定继续或结束 | 替代业务系统做最终决定 |

所以「模型能直接搞定」这句话只对了一半：**能生成，不等于能执行，也不等于结果可信。**

## 三个高频追问

### 1. 同一对话里它记得刚才的代码，不是有记忆吗？

常见实现是应用保存历史消息，下一轮请求时重新注入上下文；跨会话记得偏好，则是产品额外做了长期记忆存储。两者都不是模型修改了自身参数。

### 2. 我手动把制度贴进对话，不就是 RAG 吗？

手动贴资料只是**提供了上下文**。RAG 多了「根据问题去知识库检索」这一环；而且 RAG 不必须用向量数据库（关键词、向量、混合检索都可以），也不等于重新训练模型。

### 3. 它自己输出了 JSON，直接落库不就行了？

JSON 能解析只证明**格式正确**，不证明字段、状态、金额正确。关键数据要来自可信系统，写操作要过权限与业务规则；退款、支付这类高风险动作还需要用户确认或人工审批。

## 面试回答要点

- 用一句话钉住边界：**模型生成内容，应用负责上下文、数据、权限、执行与校验**。
- 区分「查询」和「修改」：前者错了是信息问题，后者错了是业务事故。
- 知道 MCP 只是工具接入协议之一，不是接入工具的必要条件。
