# 学习自测：上下文翻倍算力就 4 倍？注意力热力图能解释模型吗？

> 📚 参考：[Attention 注意力机制](/概念与原理/17ai/s_ai_10-attention) | [一次生成的链路与推理性能](/概念与原理/17ai/s_ai_33-inference_pipeline) | [Context Budget](/概念与原理/17ai/s_ai_36-context_budget)

**场景**：评审会上两种说法——「上下文翻倍算力就是 4 倍，所以长上下文没意义」，以及「把注意力热力图贴出来，就能解释模型为什么这么回答」。

**考察点**：O(n²) 的适用边界、延迟/显存/费用的区别、注意力权重的解释力边界。

::: details

## 核心回答

两句话都对了一半，也都在该谨慎的地方下了绝对结论。

### 说法一：上下文翻倍 → 算力 4 倍

**成立的部分**：对**标准密集自注意力**，处理长度为 n 的已知序列时，位置对关系随 n² 增长。

**不成立/不能外推的部分**：

| 说法 | 问题 |
| --- | --- |
| 延迟一定 4 倍 | 延迟还受硬件、批处理、实现影响；Decode 阶段是逐 Token 的 |
| 显存一定 4 倍 | KV Cache 随长度与并发增长，但不是同一比例 |
| 所有模型都这样 | 稀疏注意力、滑动窗口、FlashAttention 各不相同 |

更关键的是：**窗口上限 ≠ 每次请求更贵**。真正花时间花钱的是**实际发送的上下文长度**，不是模型支持的上限。

### 说法二：注意力热力图能解释模型

**不能直接当解释。**一个权重只是「某一层、某个头、某个查询位置」上的分配比例，它不告诉我们：

- 这个词在全文中是否重要；
- 最终结论的完整原因；
- 模型有没有正确执行规则。

输出还受其他头、前馈网络、残差和后续层影响。多头也不能被命名成「金额头」「订单头」。

## 正确做法

1. **用测量代替推算**：记录 TTFT、Token/s、单任务成本，按输入长度分桶看曲线。
2. **按需压缩**：相关历史 + 可信资料 + 工具结果裁剪 + 输出预留（见 Context Budget）。
3. **解释力靠实验**：改一个变量看输出变化，比贴热力图可靠。
4. **长上下文做评估**：能否找到关键事实、抗干扰、引用准确。

## 面试回答要点

- 说出 O(n²) 的前提（密集注意力、已知序列），并指出不能外推延迟与显存。
- 区分「窗口上限」「实际发送量」「计费」三者。
- 说清注意力权重是局部量，不是因果解释。
- 给出替代方案：测量 + 对照实验 + 评估集。
