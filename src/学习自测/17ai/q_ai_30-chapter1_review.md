# 第一章串讲自测：模型内部 + 应用外部

> 先自答再看参考。目标不是背定义，而是把第一章的 9 个概念串成一条能讲清的链路。

## 1. 一句话说清「模型负责什么、应用负责什么」，并举 3 个「看起来是模型能力、其实是应用能力」的例子

**参考回答：** 模型只负责根据本次可见的上下文生成内容（可能附带工具调用请求）；上下文组装、取数、执行、校验、权限与状态保存都在应用侧。

| 看起来像 | 实际是 |
| --- | --- |
| 「它记得上一轮的代码」 | 应用回放了历史消息 |
| 「它查了订单接口」 | 应用执行了工具，再把结果回填 |
| 「它知道公司制度」 | RAG 检索后把片段注入上下文 |

**追问验证：** 那模型到底贡献了什么？——理解与生成、在候选动作里做选择；但它不掌握事实来源，也没有执行权。

## 2. 把「查订单 A1024 要不要人工审核」拆成链路，标出哪些必须由代码/系统负责

**参考回答：**

```text
鉴权 → 查订单（业务系统）→ 取现行规则（规则服务）
     → 代码算金额阈值/状态/期限 → 模板或模型组织表达 → 校验 → 返回
```

必须由系统负责：身份与权限、订单真实状态、规则版本、阈值计算、执行与幂等、审计。模型只在「理解诉求 + 组织表达」这一段有价值。

**追问验证：** 用户补一句「那就直接退款」呢？——执行仍归业务系统；模型只能提议，权限与风控照常校验。

## 3. 对话到第 30 轮：窗口快满、摘要把「用户说退了 3000」写成「已退款 3000」、账单翻 3 倍。先处理哪个？

**参考回答：** 先修**事实性**，再谈成本。摘要失真会直接导致错误结论，属于事故；预算裁剪与成本优化是效率问题。

顺序：① 摘要带来源/时间/确认状态，关键字段回源 → ② 按 Context Budget 裁剪（历史、RAG、工具结果）→ ③ 按任务汇总用量做成本归因。

**追问验证：** 为什么不能先砍历史省钱？——可能砍掉完成任务的必需信息，省下的钱会以错误率还回来。

## 4. 有人说「上下文翻倍算力 4 倍，长上下文没用」，又有人拿注意力热力图解释「模型为什么拒单」。怎么回应？

**参考回答：**

- O(n²) 只对**标准密集注意力 + 已知序列**成立；不能外推「延迟 4 倍、显存 4 倍」，实际还受硬件、批处理、实现影响。
- **窗口上限 ≠ 每次更贵**，真正决定成本的是实际发送的上下文长度。
- 注意力权重是「某层、某头、某查询位置」的局部量，不能当因果解释；多头也不能命名成「金额头」。

**追问验证：** 那怎么证明改动有效？——对照实验 + 覆盖真实场景的评估集，而不是贴热力图。

## 5. 向别人介绍自己做过的 AI 实验时，怎么讲清范围与边界？

**参考回答：**

1. **为什么做**：不同任务不该都调模型，金额判断更适合确定性代码。
2. **怎么做**：任务画像 → 路由 → 执行；高风险操作留给业务系统。
3. **怎么验证**：跑了哪些用例（订单不存在、阈值边界、超时、图片不可用）。
4. **边界**：本地模拟数据、图片分支未接视觉模型、未覆盖真实授权与并发。

不宜说成：没跑过的「已实现」、没测过的「准确率 95%」、没上线的「生产级」、把课程示例说成自己的项目。

**追问验证：** 课程代码没跑通能说「实现」吗？——只能算「分析/学习」；跑通并测过才说「实现/验证」。
